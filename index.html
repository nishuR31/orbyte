orbyte is a JavaScript/TypeScript runtime with a native JIT, a compatibility runtime for the rest of the language, and an orb build --native path that emits a standalone executable. One CLI, shaped like Node and Bun.

Download

Pick your platform. Each archive contains the orb binary and the runtime static library that orb build --native links against.

Linux x86_64orb-linux-x86_64.tar.gz Linux aarch64orb-linux-aarch64.tar.gz macOS Intelorb-macos-x86_64.tar.gz macOS Apple Siliconorb-macos-aarch64.tar.gz Windows x86_64orb-windows-x86_64.zip Windows aarch64orb-windows-aarch64.zip

Or install with a script (Linux / macOS):

$ curl -fsSL https://raw.githubusercontent.com/nishuR31/orbyte/main/scripts/install.sh | bash

Windows (PowerShell):

PS> irm https://raw.githubusercontent.com/nishuR31/orbyte/main/scripts/install.ps1 | iex

Already installed? orb self-update --check reports whether a newer release exists; orb self-update replaces the binary in place and keeps the previous one as orb.old. Re-running the install script does the same thing. Updates are explicit — no background updater, no telemetry.

Archives are produced by the release workflow when a v* tag is pushed. Until the first release, build from source with cargo build --release. Verify with orb --version.

What it does

The native subset is deliberately small; everything else still runs through the compatibility runtime instead of being miscompiled.

native

JIT + AOT

One IR, two backends: in-memory Cranelift JIT for orb run, relocatable object plus linker for orb build --native.

compat

JS / TS / JSX

SWC erasure and Boa execution cover TypeScript, JSX, ES modules, CommonJS, timers and fetch.

cli

Node/Bun-shaped

run, test, repl, inspect, check, package scripts and delegated Bun commands.

third-party

Type checking

orb typecheck file.ts runs the vendored tsz checker in-process — thanks to its developers. Testing and contributions welcome.

standalone

No runtime needed

AOT output links the Rust runtime statically. The resulting executable needs no Node, Bun or orbyte install.

cross-platform

Three operating systems

CI checks, tests and an AOT smoke test on Linux, macOS and Windows, including ARM targets.

safe by default

Reject, never miscompile

Programs outside the statically typed subset are diagnosed or routed to the compatibility runtime.

Limitations

Where orbyte is today. These are real boundaries, not TODOs hidden in the demo.

  • AOT covers the native subset only. TypeScript, JSX, ES modules, async and most dynamic JS have no native IR yet. They run through orb run or Bun.
  • AOT linking needs a toolchain. cc on Unix or the MSVC linker on Windows, plus the shipped libruntime.a / runtime.lib beside the binary.
  • No built-in HTTP server or SQLite. fetch is backed by curl; http.createServer() is not implemented.
  • Node built-ins are shims. The path shim uses POSIX semantics on every platform; os.EOL and tmpdir are platform-aware, but full Node parity is not a goal yet.
  • Some development scripts need Bash. The tests/ and examples/ helper scripts are not part of CI; POSIX shell syntax in package.json scripts needs Git Bash on Windows.
  • Early project. Version 3.0.0, English-only docs, no stable API guarantees for the embedded compatibility runtime yet.
